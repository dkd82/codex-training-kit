Comment utiliser ces ateliers

  • Tout ce que vous faites aujourd'hui se passe sur un petit projet, pulselab, écrit comme l'est souvent du code de recherche : il fonctionne, il n'est pas documenté, il a peu de tests, et il cache quelques pièges.
  • Les ateliers suivent les modules de la formation. Chaque atelier a objectifs, étapes numérotées, un mode suggéré, des vérifications et des livrables. Cochez chaque étape une fois terminée (vos coches sont enregistrées dans ce navigateur).
  • Kilo Code : chaque étape nomme un mode (CHAT, PLAN, EDIT, AGENT, REVIEW). Le tableau ci-dessous donne l'agent Kilo Code qui y correspond (Ask, Plan, Code, Debug) ; vérifiez-le dans votre version, car les noms peuvent différer. Si un agent manque, émulez-le (tableau ci-dessous) et notez-le dans votre journal.
  • Les prompts sont à vous d'écrire. Les encadrés en pointillés donnent une structure à trous : le six blocs (objectif, contexte, contraintes, exemples, format, vérification). L'objectif est de vous entraîner à les rédiger.
  • Les créneaux horaires sont indicatifs. CORE TP sont la priorité ; un STRETCH TP est à faire si le temps le permet.
Règles de sécurité, toute la journée : aucun secret, aucune donnée confidentielle et aucun résultat non publié dans un prompt (les données de ce projet sont synthétiques). Commitez avant toute action de l'IA qui peut modifier des fichiers, et lisez le diff ensuite.

Les cinq modes et leur équivalent dans Kilo Code

  • Vérifiez la dernière colonne dans votre installation de Kilo Code (les noms peuvent différer selon la version : Ask, Plan, Code, Debug). Si un mode n'existe pas, utilisez l'émulation ci-dessous.
ModeSignificationDans MON outil, ça s'appelle…
CHATQuestion / réponse, aucun changement de fichier
PLANPlanification uniquement, rien n'est modifié
EDITDes modifications ciblées que vous relisez une par une
AGENTAutonome : lit, modifie, exécute des commandes
REVIEWRelecture en lecture seule d'un diff ou d'un fichier
  • Pas de mode PLAN ? Demandez en CHAT : « Ne pas écrire de code. Donne-moi un plan numéroté : fichiers à modifier, ordre, risques. »
  • Pas de mode AGENT ? Travaillez en CHAT/EDIT, appliquez les changements vous-même et lancez les commandes vous-même. Notez l'effort supplémentaire dans votre journal.
  • Pas de mode REVIEW ? Collez le diff dans CHAT et demandez uniquement des commentaires, pas de réécriture.

Règles d'or pour chaque atelier

  • Créez une branche et committez. Une branche par atelier, des petits commits, pour que tout changement de l'IA soit relisable et réversible.
  • Vérifiez. Lancez les tests, lancez le code, ouvrez les fichiers que l'assistant cite. Une réponse assurée n'est pas une preuve.
  • Petits pas. Un seul changement par prompt. Redémarrez une session qui a dérivé.
  • Vous êtes propriétaire de ce que vous commitez. Lisez chaque ligne de chaque diff que vous acceptez.
  • Tenez votre journal IA (bas de page) : prompt → ce qui s'est passé → comment vous avez vérifié → verdict → leçon.

Tâche : ajoutez une fonction pulse_widths_fwhm(x, fs, idx) dans un nouveau fichier pulselab/pulses.py. Il retourne le largeur à mi-hauteur (en secondes) de chaque pulse d'un signal, à partir des indices d'échantillon idx des maxima des pulses (tels que retournés par find_pulses). La référence de x est autour de 0 V. Si le niveau de mi-hauteur n'est pas franchi avant la fin de l'enregistrement, la largeur de ce pulse est NaN.

1.2.1Copiez les tests d'acceptation (ils définissent ce qu'est « terminé »)HUMAN3 min
  • Créez tests/test_pulse_width.py avec les tests ci-dessous. Ils échouer maintenant (le module n'existe pas). Ils contiennent une vérification analytique : une gaussienne d'écart-type σ a une FWHM = 2√(2 ln 2)·σ.
tests/test_pulse_width.py
import numpy as np
import pytest

from pulselab.pulses import pulse_widths_fwhm

FS = 1000.0
SIGMA = 0.01                       # s   ->   FWHM = 2 * sqrt(2 ln 2) * sigma = 0.023548 s


def _gaussian_pulse(center_s, amp=1.0, n=1000):
    t = np.arange(n) / FS
    return amp * np.exp(-0.5 * ((t - center_s) / SIGMA) ** 2)


def test_gaussian_fwhm_is_recovered():
    w = pulse_widths_fwhm(_gaussian_pulse(0.5), FS, [500])
    assert w[0] == pytest.approx(2 * np.sqrt(2 * np.log(2)) * SIGMA, rel=0.03)


def test_amplitude_does_not_change_the_width():
    a = pulse_widths_fwhm(_gaussian_pulse(0.5, 1.0), FS, [500])[0]
    b = pulse_widths_fwhm(_gaussian_pulse(0.5, 5.0), FS, [500])[0]
    assert a == pytest.approx(b, rel=1e-6)


def test_two_pulses_give_two_widths():
    x = _gaussian_pulse(0.3) + _gaussian_pulse(0.7)
    assert pulse_widths_fwhm(x, FS, [300, 700]).shape == (2,)


def test_pulse_cut_by_the_end_of_the_record_gives_nan():
    assert np.isnan(pulse_widths_fwhm(_gaussian_pulse(0.999), FS, [999])[0])


def test_no_pulse_gives_an_empty_array():
    assert pulse_widths_fwhm(np.zeros(100), FS, []).size == 0
Vérification avant de continuer
